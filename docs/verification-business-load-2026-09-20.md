## 业务覆盖与修复

12 条对话覆盖闪退与扣款、配送与退款、账户安全与登录、发票与人工升级、退款阶段、缺失政策、要求直接退款、同会话承接、同用户新会话、不同用户复用会话 ID，以及 500 故障。10 条独立检索包含 8 条有答案、2 条无答案问题。

实际运行发现并修复了以下问题：

1. **复合请求漏路由。** 对明确的闪退与多扣款等次要领域信号补足领域分数，并增加基础否定及已解决措辞过滤。账户安全归入 Technical，由其同时处理账户保护与登录恢复，避免落到 Billing 后出现职责拒答。
2. **执行能力表述不准确。** 提示词与 Skills 明确系统不能实际查询订单、支付流水、退款、改发票或连接真人；不得编造操作入口或声称操作已完成。退款说明明确审核 1–3 个工作日、审核通过后到账 5–7 个工作日的不同阶段。
3. **跨会话事实混用。** 结构化实体为空仍无法阻止模型从画像中引用另一笔订单或退款意愿。现在 `/chat` 生成仅使用当前会话消息与摘要，历史摘要和画像继续保存，但不自动注入当前回答。当前会话实体承接继续保留。新增自然语言订单号检查与上下文回归测试，验证新会话及未给订单号的故障请求不引用旧订单。

第三项是明确的行为收缩：本轮没有实现经用户确认的跨会话事实复用。不同用户复用 `conv_id` 的样本只验证客户端标识维度的分离；当前没有服务端登录鉴权，不能据此声称已验证权限隔离。

### 仍存在的内容问题

- 安全回答中“重置后原会话通常失效，可阻断陌生设备”，以及缺失发票政策时补充跨月、已报销的处理说法，没有冻结资料支持。需要进一步约束资料外推断。
- 同会话追问正确承接订单 B20260919008，但没有充分利用已知的 299 元，仍列出订单号、金额等材料清单。
- 配送退款回答没有直接澄清当前发货与收货状态；闪退加扣款回答偏长，并出现“下一个协同 Agent”等内部表达。

检索首位命中不能证明回答逐句有据：独立 `/search` 请求不等于 `/chat` 实际注入上下文，当前 Trace 不包含文档 ID。两个无答案题中，发票政策有配套回答测试，航空里程仅测试检索。模型别名、生成随机性及有限样本也限制了结论；未检验所有英文、复杂否定与开放表达。

## 并发实测

参数为 **4 个工作线程、8 个排队槽、1000 ms Agent 执行时限**；正常模型替身等待 30 ms。使用生产编排器、Agent、提示词处理与线程池，绕过 HTTP、意图识别、RAG、Redis、回答校验和外部模型。它是编排机制的受控负载实验，不是整个系统或真实模型的容量压测。

| 阶段 | 请求数 | 完全成功 / 部分成功 / 全失败 | 拒绝请求 | 超时请求 | 全请求 P95（ms） | 完全成功 P95（ms） | 完全成功请求/秒 |
| --- | ---: | --- | ---: | ---: | ---: | ---: | ---: |
| 单域正常 | 40 | 40 / 0 / 0 | 0 | 0 | 34.589 | 34.589 | 122.899 |
| 双域正常 | 40 | 40 / 0 / 0 | 0 | 0 | 33.542 | 33.542 | 61.247 |
| 队列饱和 | 20 | 12 / 0 / 8 | 8 | 0 | 93.711 | 93.733 | 127.609 |
| 慢调用超时 | 8 | 0 / 0 / 8 | 0 | 8 | 1001.760 | — | 0 |
| 一个领域失败 | 12 | 0 / 12 / 0 | 0 | 0 | 32.054 | — | 0 |
| 全部领域失败 | 12 | 0 / 0 / 12 | 0 | 0 | 0.884 | — | 0 |
| 同线程池恢复 | 40 | 40 / 0 / 0 | 0 | 0 | 31.998 | 31.998 | 127.347 |

饱和阶段观测到最多 4 个活跃线程、8 个排队任务，20 个同时发起的单域请求中 8 个被拒绝。慢调用阶段 8 个请求全部报告超时。12 个部分失败请求均保留 Billing 的成功结果；恢复阶段复用原线程池，40/40 完全成功。

P95 采用最近秩法；“—”表示无完全成功样本，JSON 中为 `null`。全请求与成功请求的分位数使用不同样本数，前者可以略低于后者。部分成功不计入完全成功吞吐，快速错误返回也不算成功。独立重算核对了原始样本、结果分类、失败原因、域计数、分位数与吞吐。

这些毫秒与吞吐值来自短时闭环负载和固定延迟替身，不能写成线上 QPS 或 `/chat` 的 P95。每阶段重建 Agent 与编排器，但始终复用执行器；故障替身响应中断，因此恢复结论不覆盖真实 HTTP 连接或所有业务组件。未做持续高压、开放到达率、多进程或 GC 稳态容量测试。完整规则见 [并发验证说明](load-testing.md)。
