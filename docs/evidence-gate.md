# 逐项依据审计与失败回答处理

触发问题：用户追问“是不是某入口”时，旧回答会先断言“不是”再说无法确认；旧验证器常被后半句解释误导。并且即使校验失败，原草稿仍被返回并写入会话。

本次改动：Java按中文句末标点和换行切分回答，生成A0、A1等句子编号。模型逐句分类为事实、明确未知或建议，并给出支持/未知/矛盾及来源编号。一句含多个分句时要求核对全部内容，以最弱依据判定。Java检查每个句子恰好审核一次、字段有效、事实的来源编号存在；未知事实、矛盾、遗漏句子或重复编号均不能被总的pass=true覆盖。缺少审计或解析失败也不通过。编号协议避免要求模型逐字抄写回答导致的格式误拒绝。

主张分类和证据含义仍由模型判断，代码的来源编号检查仅验证来源存在，不是语义正确性的证明。句子覆盖不等于分句语义覆盖，也无法证明模型没有漏看某个事实。不能把本机制称为绝对防幻觉。

/chat对未通过草稿只修订一次，并重新校验；再次不通过或校验服务不可用时返回明确的无法可靠回答说明，verified/grounded仍为false。只将最终返回文本写入assistant会话消息，原因保留最初失败与修订判定。校验失败的草稿仍可能存在于内部调试轨迹，不作为本轮最终答复。

通过的草稿不增加修订调用；需要修订时最多增加一次生成与一次校验。因此可能增加延迟及模型用量，本次是质量回归，不是并发性能压测。

Java测试覆盖不可信总标记、伪造引文、错误结构、未知事实、矛盾、正确事实/未知、最多一次修订、校验不可用及最终会话写入。

低置信度OTHER意图在已有用户历史时进入正常Agent处理，避免固定首轮澄清句丢弃上下文。原首轮澄清机制保留。明确已知时间锚点不应被说成未知，未提供订单字段不应被扩写成系统没有会话存储。

Docker构建增加BuildKit Maven依赖缓存，减少网络下载失败后重复拉取全部依赖。构建仍编译项目源码；镜像构建跳过测试，完整Java测试单独执行。

真实验证器的固定合成上下文正反例与Docker真实对话分开保存。首轮及中间失败均保留，样例预期不为结果修改。新题在运行前冻结，单独检查可回答性，统一拒答不算回答成功。复核由AI完成，不是独立人工盲测。

代码检查另覆盖有限的已知失败模式：位置确定短答与未知解释并存、缺失订单却声称已提供、未知页面建议、未支持的重置操作步骤/解锁权限/按钮功能映射、未知规则关系被说成排除适用。规则有明确适用条件和正反测试，但不是通用语言理解或绝对防幻觉系统。

新增绑定条件检查：知识仅支持绑定手机号重置时，号码可用不证明它已绑定当前账号。对缺少绑定陈述或明确未绑定的直接肯定答复，要求补充绑定前提再审核。该检查是有限文本模式，不能识别所有同义改写；测试同时覆盖已绑定、未绑定、未知绑定和条件性答复。

随后一轮42条仍发现5次事实失败：一次把字段缺失说成没有存储能力，四次把可用恢复方式扩写成唯一方式。最终再补充能力事实和两类有限检查，并针对受影响路径复测；这些失败完整保留，不纳入最终通过数。系统具备会话存储不等于承诺永久保存；知识说明绑定方式可用也不证明所有其他方式被禁止。

纯会话记忆/存储能力问题不检索业务政策，避免订单号和金额关键词将重复扣款材料带入无关问题。若同时询问退款、登录等业务仍保留检索；测试覆盖纯能力问题和混合业务问题。这一范围识别基于有限的显式短语，不是对所有元问题的分类器。

## 复现

在项目根目录配置原有模型环境变量并启动Docker，依次执行（每次用新的输出目录，会消耗模型额度）：

```powershell
docker compose build echomind-java
docker compose up -d redis chromadb
python demo/run_wording_regression.py --cases evaluation/evidence-gate-regression-cases.json --output-dir evaluation/local-regression
python demo/run_wording_regression.py --cases evaluation/evidence-gate-holdout-cases.json --output-dir evaluation/local-holdout-1
python demo/run_wording_regression.py --cases evaluation/evidence-gate-holdout-cases.json --output-dir evaluation/local-holdout-2
```

每次采集建立独立数据目录和合成会话，固定关闭模型降级并检查3个Skills，结束移除临时应用容器。不清空业务Redis。模型输出仍可能波动，复现是复现过程，不保证逐字相同或永远通过。

本次没有重新做真实并发性能测量；新增修订调用可能增加成本和延迟，旧压测数字不能当作此次版本的真实模型性能。
