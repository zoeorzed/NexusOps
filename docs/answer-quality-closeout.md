# 回答质量收尾验证（2026-09-27）

原有 `verified`/`grounded` 只给布尔值，无法区分内容缺少依据、验证器误判和校验服务不可用。本次 `/chat` 新增 `verification_reason`，直接保留原验证结果的理由，未把失败标记改成通过。

有理由的首轮复测确认，验证器曾将检索到的重复扣款说明当成当前用户的争议事实，或忽略当前用户已说明的付款渠道。现版先由本轮用户消息和本会话判断场景，再核对知识规则；用户陈述可支持条件性政策说明，但不代表后台核验。同时修正无依据的绝对换卡限制，以及假定页面必有请求编号的措辞。

## 已知措辞问题
