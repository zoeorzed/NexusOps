## 关键实现与可讲清的边界

- Agent 使用专用有界 `ThreadPoolExecutor`，默认 8 线程、32 队列；执行阶段统一 30 秒截止时间包含排队。超时、拒绝、异常会记录领域失败与 Trace，同时保留及时完成的其他领域回复。代码采用 `Future` 跟踪、取消任务。
- 取消只请求线程中断，不保证底层 HTTP 立即停止；预算不包含前置意图识别、检索、后置回答校验或同步记忆处理，不能承诺整个 `/chat` 30 秒完成。
- Redis 摘要生成在 Lua 外进行，Lua 核对列表长度和完整快照后才原子保存摘要、截断原消息；期间有并发写入就放弃过期压缩。摘要异常时保留原文。它保证本次列表压缩条件检查，不代表跨系统事务。
- Judge 无效或异常不再用占位质量分伪装有效评分；失败样本保留在总数中。自动 baseline 比较要求数据、模式、指标版本一致，保存必须显式开启。
- 当前无真实退款、支付流水查询、工单写入工具；客户端 `user_id` 是演示标识，没有生产级登录鉴权。ChromaDB 仍是预留，主召回是本地 BM25 与 hash vector 混合检索。

## 复现

先准备独立无密码 Redis，在项目根目录执行 `./scripts/verify.ps1 -RedisPort 6379`；再运行 `./scripts/run-evaluation.ps1 -Offline`。

真实评测需要以 `deepseek` Profile 配置模型并启动服务，运行 `./scripts/run-evaluation.ps1 -Output target/new-intent-report.json`。真实演示需新的空 `ECHOMIND_DATA_DIR`，运行 `python demo/run_demo.py --base-url http://127.0.0.1:8080 --output demo/results/new-run.json`。不要覆盖本次或历史证据；运行会产生模型 API 用量。
